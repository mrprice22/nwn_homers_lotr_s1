  • Legendary Level Skill Points Exploit
    ExploitShipped · Merit awardedJuly 13th, 2026Credit: Rajmund (Ray)
    Epic leveling: you get N skill points. When spending, it raises the skill. Then when you are down to 1 point, you pick something but choose to start over. 
    You start anew with all the skill points to spend. But you keep the N-1 skill points spent.

    DM: Fixed. The leveler applied each pick the instant you confirmed it, but only spent the level itself on the very last confirmation — so backing out (or walking away, or disconnecting) kept the picks and left you eligible to level again. The same hole handed out unlimited feats and ability points, not just skill points.

    The level-up is now a single transaction: nothing touches your character until you confirm on the final page, and then it all applies at once. "No. I want to start over." now genuinely starts you over, with your full pool back.

  • [Anvil] Adhoc toggle reboot on empty with warning to players
    EnhancementShipped · Merit awardedJuly 2nd, 2026Credit: HomelessSon (Server Admin)
    As a Server Admin, 
    I want to be able to push module updates that require a reboot without interrupting players or logging in to ask them to log out. 
    • Use Anvil plugin to trigger an in-game alert that server will reboot when next empty (also update on-login message to newly joining players of the same until reboot happens). 
    • Support custom message to players explaining what updates to expect/look forward to when server next reboots. 

    Implemented 2026-07-02: The Anvil ServerRestartManager now honours a reboot-on-empty control file. Arm it from the shell with bin/reboot-on-empty "your message" (add --nwsync to also rebuild the client download manifest) after deploying an update — no in-game login needed. While armed, online players get a broadcast + shout warning and newly joining players see an on-login notice carrying the custom message. Once the server sits empty for ~45s it saves all characters, shuts down cleanly, and a host systemd .path unit restarts just the server service onto the freshly deployed module (rebuilding NWSync first when requested). The arm flag is deleted before shutdown so it can never boot-loop, and bin/reboot-on-empty off cancels a pending reboot. Docs in rebootSchedule.md.

  • Bard song damge modifier (not working again)
    DefectShipped · Merit awardedJune 24th, 2026Credit: Y a z k i r
    The damage on bard song isn't correct: 38 bard, 121 perform, giving +D4 damage? (expecting +6 instead at this skill and bard level, per Bard Song customized to mirror the customized Curse Song) -- Bruno Mars is the character

    Root cause was that EffectDamageIncrease takes a DAMAGE_BONUS_* constant, not a flat integer — the raw value 6 was being read as DAMAGE_BONUS_1d4, so the top tier rolled 1d4 instead of applying a flat +6. The damage amount is now routed through IPGetDamageBonusConstantFromNumber() so each tier maps to the correct constant (6 → flat +6). The identical bug was fixed in the matching Curse Song (x2_s2_cursesong) damage tiers (raw 6/8/10 were rolling 1d4/1d8/2d6, now flat −6/−8/−10). Tiers 1–5 were always correct and are unchanged; only the damage column was affected.

  • Weapons with both Attack Bonus (AB) and Enhancement Bonus (EB) appear to mis-calculate stats
    DefectShipped · Merit awardedJune 23rd, 2026Credit: Piskan (Alec Cain)
    Weapons carrying both an Attack Bonus and an Enhancement Bonus were misleading you: the NWN engine applies only the higher of the two to your attack roll, so any Attack Bonus at or below the Enhancement Bonus was dead weight on the character sheet. This is hardcoded engine behaviour with no toggle, so every weapon in the module was audited instead — 253 weapons had the two properties collapsed into a single Enhancement Bonus, raised to a balanced value where the old Attack Bonus was higher. Copies already in your inventory were repaired automatically.

    If you keep old copies in the Bank of Bree, take them out and leave them in a character's inventory overnight — the nightly 3am reboot scans character files, not storage boxes, so banked items will not be fixed until they are carried.
