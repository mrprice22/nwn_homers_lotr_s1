# Boss respawn tracker ("Roll of the Fallen") — maintenance

The Well of Eru board that lists currently-slain bosses with respawn countdowns
and who killed them. Player-facing docs: `docs.manual/Customizations.html#boss-respawn-tracker`.

## Moving parts

| Piece | Where |
|-------|-------|
| Registry + all DB/board logic | `unpacked/brd_db.nss` (campaign DB `respawndb`: `boss_registry`, `boss_alias`, `boss_deaths`). The `BRD_SeedBoss`/`BRD_SeedAlias` block between the `// BEGIN/END GENERATED REGISTRY` markers is **machine-generated — do not hand-edit it** |
| Registry generator | `bin/gen-boss-registry.py` (+ shared `bin/boss_index.py`) — scans `unpacked/`, applies the boss rule, rewrites the marked block in `brd_db.nss`. Run on demand; see "Refreshing the registry" below |
| Death hook | one `BRD_RecordDeath()` call in `unpacked/bst_ondeath.nss` (rides the bestiary's runtime OnDeath wrapper — covers every boss with no per-blueprint edits) |
| Init / reset | `BRD_InitDb()` in `unpacked/onmoduleload.nss` — reseeds the registry from source and **wipes `boss_deaths`** (a restart revives every boss) |
| Board | placeable tag `boss_respawn_board` in `thewelloferu.git.json` (`Conversation: brd_sign`, `OnUsed: brd_use`), dialog `brd_sign.dlg.json`, scripts `brd_use` / `brd_vis_0..8` / `brd_open_0..8` / `brd_page_n|p` / `brd_has_next|prev` / `brd_back` |
| Custom tokens | **6300–6313 reserved** (6300-6308 rows, 6309 header, 6310-6313 detail) |
| Build gate | `tests/check_boss_registry.py` in `tests/smoke-test` — every repack verifies the registry against `unpacked/` |
| Wiki page | `docs/creatures/bosses.html` (+ `module-index/bosses.json`) — generated by nwn-wiki (`load_boss_registry`/`render_bosses_index` in `GIT/nwn_manager/bin/nwn-wiki`) by parsing the **same `BRD_SeedBoss` rows**, so game and wiki can't drift; editing `brd_db.nss` updates both (wiki at the next scheduled refresh). A seed resref with no creature page renders unlinked and logs to `module-index/lookup_warnings.json` |

## What counts as a boss (the rule)

The registry is **generated from a rule**, not hand-curated. A creature is a
boss when its blueprint has:

- **`ChallengeRating > 60`**, and
- **exactly one live instance** in the world — one placement and no encounter
  slot (`placed`), OR no placement and exactly one `MaxCreatures=1` /
  `Respawns=-1` / `Reset=1` encounter instance (`encounter`), and
- it is **not plot or immortal** (an unkillable NPC can't sit on a kill
  tracker), and
- it is **not a merchant / utility NPC** (Merchant faction, the CR-artifact
  cap, or the `EXCLUDE` denylist in the generator).

Same tag in **different** areas is fine (the two Khamuls); the same tag in the
**same** area means several copies are alive at once → dropped as
not-single-instance (e.g. the paired Dol Guldur Gate Keepers).

## Refreshing the registry

To change what appears on the board and the wiki Bosses page, **edit the rule /
levers and regenerate — never hand-edit the seed block**:

1. Adjust as needed in `bin/gen-boss-registry.py`:
   - `EXCLUDE` — resrefs to keep off the board even though they pass the rule
     (vendors, props). This is the main curation lever.
   - `INCLUDE` — resrefs to force on even though they're **below** `CR_MIN`
     (the escape hatch for a sub-60 boss you want tracked, e.g. Xanith). Add
     each variant blueprint too if it aliases.
   - `CR_MIN` / `CR_ARTIFACT` — the CR floor and the absurd-CR cap.
2. `python3 bin/gen-boss-registry.py` — **dry run**. Read the report: included
   list, alias groups, **respawn warnings** (bosses whose OnDeath won't bring
   them back — see below), merchant-ish names to review, and a diff vs. the
   current registry.
3. `python3 bin/gen-boss-registry.py --write` — rewrites the marked block in
   `brd_db.nss` (idempotent; safe to re-run).
4. `python3 tests/check_boss_registry.py` — the **independent** build gate
   (it re-derives placements/encounters itself, so it catches generator bugs).
   Then repack (the smoke-test runs it again). New content that qualifies does
   **not** break the gate — it simply won't show until you regenerate, so
   re-run the generator after adding bosses (like `gen-roadmap.py`, it's
   on-demand, not part of repack).

### Respawn coverage (report-only)

CR>60 + single-instance says a creature *can* be tracked, not that it actually
comes back. The generator classifies each placed boss's OnDeath:

- **standard** — reaches `SE_DoCreatureRespawn` (flat 900 s; `nw_c2_default7`,
  `x2_def_ondeath`, `staticspawn`, `deathalert`, `dunharrowdeath`). The board's
  countdown is accurate.
- **legacy** — re-creates via the old `StaticSpawn`/`CreateObject` path; the
  boss returns but on a non-standard timer the board's 900 s may not match.
- **none** — stays dead until a server restart. The board would count down and
  falsely clear it. **Currently none** — the three that were like this were
  fixed to the standard 900 s (see below).

To make a `none` boss truthful, add `#include "se_respawn_inc"` and a guarded
`SE_DoCreatureRespawn()` (skip when the tag contains `NSP`) to its OnDeath, then
regenerate. **If the OnDeath script is shared with non-boss creatures, don't
edit it** — point the boss's blueprint `ScriptDeath` at a small wrapper that
`ExecuteScript`s the original then respawns. Done for the original three:
`skinnerdeath` (Rancid Skinner, sole user — edited directly), `demondeath`
(Fell Beast, sole live user — edited directly), and Wart Gondorian Gate
Captain, whose `hotuxpfix` is shared by 7 Black Numenorean mobs → new
`wartdeath.nss` wrapper + `gondorianguar005.utc.json` `ScriptDeath` repointed.

Encounter bosses carry their real `ResetTime` as `respawn_seconds` (the
generator reads it; the gate enforces they match), so their countdowns are
accurate without any standardization.

## Don't break it

- **Don't hand-edit the seed block** between the `// BEGIN/END GENERATED
  REGISTRY` markers in `brd_db.nss` — the next `gen-boss-registry.py --write`
  overwrites it. Change the rule/levers in the generator instead. Keep the
  `BRD_SeedBoss(...)` literal shape (`… CR.0, respawn, "type");`): the game,
  the gate, **and** the wiki (`load_boss_registry` in `nwn_manager/bin/nwn-wiki`)
  all parse that exact text.
- **Don't remove or reorder the `BRD_RecordDeath(oCre)` call** in
  `bst_ondeath.nss` past the early-return blocks — it must run even when no PC
  gets kill credit (trap/DM kills still leave the boss dead).
- **Don't give a tracked boss a second placement or encounter slot** (and
  don't re-tag one) without regenerating — the build gate will catch the drift;
  fix it by regenerating, don't weaken the test.
- **Two same-tag bosses exist** (`Khamul` on both `creature007` and
  `creature007_2`). Liveness checks are tag **+ area** (`BRD_BossAlive`);
  keep `area_resref` correct if a boss is ever moved.
- **Encounter instance overrides repurpose blueprints**: the five `moriabyss`
  instances in `theabyssofmoria` are trash overrides; only the
  `thebalrogofmoria` instance spawns the Balrog. Same trick spawns Legolas
  from a `nw_aberration` instance in `area023`. Always inspect the
  instance-level `CreatureList` in the `.git.json`, never trust the `.ute`
  alone.
- **Tokens 6300–6313 are claimed** — pick a different range for new systems.
- The `boss_deaths` wipe in `BRD_InitDb()` is intentional (restart = all
  alive). Don't "fix" it into persistence without also persisting respawn
  timers, which don't survive a restart.
